# v8.3 · 手动联机流程简化

本轮保留全部现有牌桌、规则及前几轮改动。应用版本8.3.0，schema／protocol8，连接描述封装v1；没有新增信令服务器、云后台、账号、数据库、网络路由或运行时依赖。

## 玩家流程

1. 房主建桌后打开「邀请好友」，生成并复制／分享邀请链接。
2. 好友打开链接，邀请会填好并切到「加入好友」；确认昵称后点击「加入并生成回应」。
3. 好友复制／分享回应给房主，并保留本页。
4. 房主粘贴回应，短暂输入防抖后校验并连接，不再要求多点一次确认。保留接收回应的重试按钮，方便键盘或复制不完整后的重试。
5. 收到本人牌桌快照后显示「已入席」和「进入牌桌」。下一位好友使用新生成的一份邀请。

仍需往返交换一次邀请和回应；没有房间号自动寻桌，也没有代收回应的远端服务。每份邀请对应一条好友连接。原始TX1邀请／回应继续可用，输入框同时接受链接和连接码。

邀请使用当前网页的来源和项目路径，清除无关查询与旧fragment；兼容`/sanguosha-tongxi/`静态项目路径，不擅自指向未更新的公网版本。当前页面若为`localhost`，界面会提示只能本机访问：其他设备需打开同一版本的公开网页后粘贴原始连接码，或各自启动同版本本地静态服务后交换连接码。线上更新由现有GitHub Pages工作流完成，部署成功需单独核对。

## 即时反馈与失败处理

- 邀请、回应准备期间按钮显示进度并防重复；再次生成邀请先清掉旧输出，避免复制到上一次的邀请。
- 系统提供分享入口时可打开分享面板；取消分享直接返回，分享失败则尝试复制。剪贴板不可用时选中文本并提示Ctrl+C，不虚报复制成功。
- 已准备好的同一回应可再次复制；同一房间、同一邀请、同一SDP的重复接收不重新建立连接。错误方向、错误房间或损坏内容给出提示，保留原有连接。
- 新邀请校验和回应生成成功后，才替换旧好友连接。准备期间切换到新桌／演练会关闭待建通道，旧任务完成不能覆盖新牌桌；取消后按钮恢复可用。
- 连接列表显示已入席昵称；尚未入席用「邀请1」等名称。直连／中继依据实际选中候选对判定，未知时只显示已建立连接，不显示IP或凭据。
- 短暂掉线先显示「网络波动」并等待自然恢复；5秒仍断开则提供重连入口，仍可继续等待。明确失败／关闭则直接提示重邀。恢复会同步最新快照，不后台重发玩家指令。
- 房主「重新连接」生成新邀请；好友入口清理旧输入并提示粘贴新邀请。保留原标签页及其sessionStorage凭据，便可认领原席位。未增加自动迁主、跨域凭据迁移或后台重新信令。

## 数据边界

- 连接描述按原有格式私下交换；链接不是加密短码，可能较长，仍受聊天应用长度限制。原始连接码入口保留。
- 邀请fragment打开后立即从地址栏移除；不通过请求向静态服务器提交。昵称可保存在本机，连接描述与TURN凭据不持久化到存档或日志。
- 输入限制30万字符；连接码及解压后JSON各限制10万。校验版本、邀请／房间标识、方向和SDP类型；解码使用字段白名单，不将外带字段传给连接或游戏。
- 席位凭据仍由原有sessionStorage和授权join处理；网络只进join／action／sync。复制、分享、状态提示不修改对局状态。

## 验证入口

- `node scripts/check.mjs`、`node --test`。
- `node scripts/browser-all.mjs`包含原14套及新增`connect-ux`；需可选Playwright，不是运行时依赖。
- `node scripts/browser-connect-ux.mjs`覆盖邀请链接预填及移除fragment、分享／复制失败、粘贴回应、多好友、重复回应、错误房间、损坏SDP、切换牌桌取消、重邀原席位及桌面／手机尺寸。
- 新场景中的连接、关闭、重邀和快照同步是真实同机WebRTC；短暂`disconnected`状态人为注入，用于验证提示、5秒计时取消与恢复分支，不能据此宣称已模拟真实跨网断连。
- 截图遮掉全部连接码和链接，输出保存在忽略提交的`output/playwright/`。完整结果见[验证记录](TESTING.md)。

未验证跨互联网NAT／TURN、Safari／Firefox、实体手机系统分享及后台切换。系统分享在回归中使用桩验证调用和失败路径；不把它描述为真实微信等第三方应用分享成功。提交和部署状态不代替这些场景的实测。
