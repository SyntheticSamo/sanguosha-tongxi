# 验证记录

日期：2026-10-27。平台：Windows，Node.js 24，桌面 Chromium / Chrome 自动化测试。

## 已通过

`node scripts/check.mjs`：12 个 JavaScript 模块语法检查通过，HTML 无重复 ID。

`node --test`：16 项测试全部通过，涵盖：

- 104 张标准牌、4 张 EX、32 种牌名、25 位武将与主要牌种数量。
- 2–8 人开局身份布局、四张起始手牌、主公公开与牌数守恒。
- 视图过滤：其他手牌、未公开身份、牌堆顺序与 token 不下发。
- 非法操作原子拒绝、旧版本拒绝、房主操作权限。
- 隐藏交牌、同栏装备替换、结算区移动、判定区传递、私下观星和有序放回。
- 阶段推进权限、原 token 重连、阵亡弃牌、胜方公开。
- 存档重复牌 / 缺牌拒绝、协议版本 / 房间 / 旧快照检查。
- 洗牌不修改输入、空牌堆回洗弃牌堆。

`scripts/browser-smoke.mjs`：实际打开四个独立浏览器上下文，使用应用界面交换邀请 / 回应，建立三个真实 WebRTC DataChannel。所有 ICE 配置为空，STUN 关闭。验证通过：

- 四席入座、选择武将、开局后各自四张手牌且总计 16 张不重复。
- 好友摸牌同步，房主交牌给好友，公开打出与清理结算区。
- 聊天中的 HTML 作为文本显示，不执行注入内容。
- 八张公开翻牌的多玩家同步。
- 房主刷新，IndexedDB 恢复，好友使用原标签页凭据重连并恢复相同手牌。
- 撤销后版本继续递增。
- 390px 宽的手机首页 / 牌桌无横向页面溢出。
- 本地演练增加和切换席位，资料库显示 25 位武将、32 种牌名。
- 浏览器无未捕获脚本错误。

桌面和手机截图已进行视觉检查。测试过程中修复了 Windows 静态根目录路径校验、旧连接状态回调和重连时旧回应显示问题。

## 验证边界

四个浏览器上下文运行在同一台机器，这是本机 P2P 实测，不是两地互联网测试。未实测跨 ISP、公网对称 NAT、TURN、中断掉包恢复、Safari / Firefox、真实手机后台暂停或 8 台实体设备。WebRTC 数据通道本身为可靠有序传输；房主长时间离线仍需手动恢复并重新交换连接信息。

没有测试「全武将自动结算」，因为产品明确采用人工裁定。技能、距离、响应顺序和胜负的桌游合法性由同桌负责。

可选浏览器脚本使用临时浏览器上下文，不读取个人浏览器资料。运行前先启动 `node scripts/serve.mjs`。如 Playwright 安装在项目外，可设置 `PLAYWRIGHT_MODULE` 为模块文件 URL，`BROWSER_PATH` 为浏览器可执行文件绝对路径。
