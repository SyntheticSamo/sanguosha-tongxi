# 同席 · 三国杀 P2P 牌桌

浏览器中的经典标准版自由牌桌。包含 25 名经典武将、104 张标准牌和可选的 4 张 EX。牌面采用原创排版，不包含官方插画。

本项目按用户选定的「桌游式自由操作」实现：牌堆、身份、牌区、回合和同步由程序管理，玩家自行处理技能、响应、伤害及胜负裁定。不是全自动规则引擎，也不包含 AI 玩家。

## 立即运行

需要 Node.js 22 或更新版本。没有必装第三方依赖，不需要 npm install。

在本项目目录的 **PowerShell** 中运行：

```powershell
node scripts/serve.mjs
```

浏览器打开 [本地牌桌](http://localhost:4173)。也可以执行 `./start.ps1`。停止时按 Ctrl+C。

这是用于加载静态文件的本地预览服务，不参与联机，也不存储玩家状态。浏览器的模块和 Worker 需要 HTTP(S) 来源，不能双击 `index.html` 用 `file://` 运行。正式使用时将整个 `dist/` 放到任何 HTTPS 静态托管，玩家打开同一份网页即可；无需部署游戏后端、数据库或信令服务。

## 邀请朋友

1. 房主「创建牌桌」，选择席位数和是否加入 EX。每人可先从资料库选择武将。
2. 房主打开「联机」，生成邀请，私下发给一位好友；同时发网页地址。
3. 好友打开网页，粘贴邀请，点击「生成回应」，将回应发回房主。
4. 房主粘贴回应并点击「接收回应并连接」。连接建立后好友自动入席。
5. 每位好友单独重复一次交换。开局根据实际入席人数发身份和四张手牌，未选武将随机分配。

连接码含网络候选信息，请私下交换。左侧短房间标识仅供辨认，**不能单独作为自动加入码**；没有中央目录服务时，需要完整邀请 / 回应来交换信令。

默认启用公共 Google STUN 来发现公网地址，不使用它传输游戏状态。可以关闭 STUN，完全不联系 STUN / TURN，通常适用于同局域网。互联网直连受 NAT 和防火墙影响；对称 NAT、校园网等可能需要 TURN。在联机面板的网络选项填写自己的 TURN ICE JSON，例如：

```json
[{"urls":"turn:your-domain.example:3478","username":"your-user","credential":"your-local-credential"}]
```

凭据仅在本页面的连接对象中使用，不写入存档、日志或项目文件。不要把真实凭据提交到仓库。本项目不附带公共 TURN 服务，也不保证任意网络都能直连。

## 本地演练

首页点击「先来一局本地演练」，增加本地席位，再开始对局。通过左侧下拉框切换控制席位，熟悉手牌、身份和操作。演练没有电脑 AI，不能接入网络玩家。演练切换会显示对应席位的私有信息；普通联机模式没有切换功能。

4–8 人按经典身份布局；2–3 人是方便演练的自定义布局：2 人为主公 + 内奸，3 人为主公 + 反贼 + 内奸。并非官方 1V1 或 3V3 玩法。5 人及以上主公体力上限加 1。

## 怎么操作

| 桌游动作 | 界面操作 |
| --- | --- |
| 使用 / 响应牌 | 选择手牌和目标，点击使用 / 打出，实体牌进入结算区；等同桌响应，再手动完成效果 |
| 转化牌 | 选择实体手牌，点击转化使用，输入如「武圣杀」「倾国闪」；系统公告并公开实体牌 |
| 装备 | 选择一张装备牌，点击装备；同一栏已有装备自动弃置旧牌 |
| 延时锦囊 | 选牌和目标，点击放入判定区；国色转化以日志注明 |
| 移动公开牌 | 点击任意席位装备 / 判定牌，可获得、弃置、放入结算区，或传给目标判定区 |
| 拆桥 / 顺手 | 选择目标后随机弃置 / 获得其手牌，或选择其公开牌操作 |
| 判定 / 五谷 | 输入张数点击翻牌，牌进入公开结算区；按需要获得或清至弃牌堆 |
| 观星 | 点击私看牌顶，按期望顺序选择，再置顶 / 置底；其他玩家看不到这些牌 |
| 仁德 / 遗计 | 选择自己手牌，指定目标，点击交给目标；对其他玩家仅公开张数 |
| 技能 | 点击技能名显示经典版提示，确认后公告；效果由同桌执行 |
| 伤害 / 回复 | 选择目标，再点击体力 −1 / +1；不会自动判定死亡 |
| 濒死 / 阵亡 | 先进行求桃，未救回时由房主在工具面板确认目标阵亡；个人牌区自动弃置并亮身份 |
| 回合 | 当前玩家或房主推进六阶段，摸牌和弃牌自行执行 |
| 胜负 | 房主在工具面板选择主忠 / 反贼 / 内奸 / 平局并结束对局 |

程序不强制距离、出杀次数、技能使用条件、响应时机或锦囊结算栈。它也不会自动执行击杀奖惩、天妒、连营等触发。每种经典技能均可通过牌区操作和体力操作进行人工结算；有歧义时以同桌商定的经典版本文本为准。选择一处牌区后，再点另一处会切换选择范围，不能混合多个牌区同时提交。

## 存档和重连

- 房主每次合法变更后将完整状态保存到浏览器 IndexedDB，只保留最近主持的一桌。
- 房主刷新后点击「恢复本地牌桌」，重新为每个好友生成邀请。好友在原浏览器标签页回应，会用 `sessionStorage` 中的席位凭据认领原席位。
- 不要同时在同一来源的多个标签页主持牌桌；最近存档会相互覆盖。
- 好友更换浏览器、清除数据或丢失原标签页凭据后，不能自动认领旧席位。当前版本没有席位转让或主持人迁移。
- 房主工具面板可导出 / 导入完整恢复 JSON；文件包含所有隐藏手牌、身份与席位凭据，只能由房主私下保管。不要发给其他玩家。
- 撤销保留递增版本号，避免旧指令再次生效；撤销不能收回玩家已经看到的信息。

## 前后端与同步

```text
dist/ui/                前端：界面、交互和连接编排
dist/backend/engine.js  后端规则内核：纯状态变换、权限、牌区守恒、私有视图
dist/backend/worker.js  后端运行入口：串行命令、去重、存档、广播、撤销
dist/backend/storage.js IndexedDB 恢复存储
dist/sync/rtc.js        WebRTC 数据通道、手动信令、分片与背压
dist/sync/protocol.js   协议版本、消息边界、快照版本检查
dist/data/             完整标准牌实例与武将资料
scripts/               本地静态预览、语法检查和可选浏览器测试
tests/                 Node 内置测试，不需要测试框架
docs/                  来源、架构与验证记录
AGENTS.md              后续修改约定
```

这里的「后端」是独立的权威逻辑层，运行在房主浏览器的 Web Worker 中。没有需要部署的传统 Node / 云游戏后端。静态托管只负责首次加载文件，不负责同步游戏数据。

房主是可信主持人，可访问其设备上的完整状态。普通玩家的网络快照只含自己手牌、自己的隐藏身份、公开区域和公共日志；不会下发牌堆顺序、其他手牌或席位 token。本项目适合可信好友，未实现对房主作弊的密码学防护，也不是竞技级反作弊系统。

协议和威胁边界详见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 验证

在项目目录的 **PowerShell** 中：

```powershell
node scripts/check.mjs
node --test
```

可选浏览器测试需要自行安装 Playwright 和 Chromium，再在运行本地预览时执行 `node scripts/browser-smoke.mjs`；可用环境变量 `PLAYWRIGHT_MODULE`（模块文件 URL）和 `BROWSER_PATH` 指定已有安装。运行项目本身不依赖 Playwright。验证范围见 [docs/TESTING.md](docs/TESTING.md)。

## 发布

将 `dist/` **内部全部文件和目录**上传到 HTTPS 静态站点，并保留相对路径即可。无需构建、数据库、WebSocket 或 API 密钥。模块和 Worker 应返回正确 JavaScript MIME 类型，托管平台不要把不存在的 `.js` 路径回退成 HTML。推荐最新桌面 Chrome / Edge；手机有响应式布局，但移动系统可能在后台暂停标签页，房主优先使用桌面浏览器。

Sites 发布元数据保存在 `.openai/hosting.json`，不属于游戏运行依赖。本次托管已按用户选择设为持链接可访问，朋友可以打开同一网址，再私下交换邀请 / 回应。公开的是静态网页；牌局与存档保留在各自浏览器，不上传到托管服务。也可以把源码包发给朋友，让每个人本地运行相同版本，再交换邀请。

资料口径与链接见 [docs/SOURCES.md](docs/SOURCES.md)。
