# 同席 · 三国杀

浏览器 P2P 身份牌桌。默认基础自动结算，可手动纠正；复杂武将技能手动处理。无需自建游戏后端或信令服务器。

## 运行

需要 Node.js 22+，无必装第三方依赖。在项目目录的 **PowerShell** 中运行：

```powershell
node scripts/serve.mjs
```

打开 [本地牌桌](http://localhost:4173)。也可执行 `./start.ps1`；Ctrl+C 停止。本机服务只加载静态文件，不传输游戏状态。不能用 `file://` 双击运行模块与 Worker。

公开站点：[三国杀 · 同席](https://sanguosha-tongxi-andy.glass-peacock.chatgpt.site)。朋友也可各自本地运行同一版本，再交换邀请。

## 建桌和选将

建桌选择人数、结算模式、牌堆和武将包：

- 纯随机：开局分配，每个历史人物最多一人。
- 点将：玩家从启用的武将包选择，所有人选完后开局。
- 五选一：每人获得五个私密候选，选完开局。候选之间不重复历史人物；八人桌需要至少40名独立人物。

收录101个版本：标准27、界标26、神话48（风火林山阴雷各8），排除神将。标准与界版分开存储，同人物的不同版本不能同时上场。技能资料尽量采用可验证的实体身份修订，版本和来源在资料卡详情；未核实的实体最新印次不冒称已核对，见 [版本说明](docs/CATALOG_VERSIONS.md)。

4–8人为标准身份布局；2–3人为自定义身份对抗，不是官方1V1。5人及以上主公体力上限+1。

## 联机

1. 房主建桌，生成邀请，连同网页地址私下发给一位朋友。
2. 朋友粘贴邀请，生成回应，发回房主。
3. 房主接收回应，通道建立后朋友入席。每位朋友分别交换一次。

短房间标识不能独立用于自动加入。默认公共STUN帮助发现公网地址；可在网络选项关闭，完全不联系STUN/TURN。局域网通常可直接连接，公网受NAT和防火墙影响，受限网络可能需要自己的TURN。自定义ICE JSON只留在本次页面内存，不记录凭据。

## 自动范围

| 系统 | 行为 |
| --- | --- |
| 回合 | 六阶段；摸牌阶段自动摸2张；弃牌到体力值后才能继续；酒加成回合结束清空 |
| 杀闪桃酒 | 出杀次数、攻击范围、闪响应、酒下一张杀+1、自用桃、濒死求桃及自救酒 |
| 距离 | 存活座次、坐骑、武器范围与基础马术 |
| 伤害 | 属性杀、铁索传导、濒死、阵亡、击杀奖励、主公误杀忠臣及常规身份胜利 |
| 常用锦囊 | 无中、拆桥、顺手、决斗、借刀、AOE、桃园、五谷、火攻、铁索重铸；逐目标无懈及反无懈 |
| 延时 / 判定 | 乐、兵粮、闪电；判定阶段先无懈再翻判定牌，可改判，再确认生效；泛用判定按钮 |
| 拼点 | 发起后双方秘密提交，同时公开比较，平点发起者未赢；技能附加效果人工执行 |
| 基础装备 | 装备替换、范围、连弩次数、青釭无视防具、仁王盾、八卦、藤甲、白银狮子、古锭刀；朱雀可通过转化选火杀 |
| 基础技能 | 马术、咆哮基础次数、无双、空城、谦逊、奇才距离；武圣、龙胆、倾国、急救、奇袭、国色、丈八的基础转化 |

锦囊无懈窗口需要各存活玩家分别点击响应或放弃，无超时自动替玩家决定。杀的闪、决斗的杀须逐张响应；有无双时界面显示还需几张。判定生效前可选择手牌，以鬼才、鬼道或房主纠正改判。

武将收录不等于所有技能已自动实现。觉醒、限定、翻面、特殊牌堆、额外阶段、武将技能触发、部分装备主动效果、以及同名技能后续修订的附加效果仍需人工处理；例如界武圣的方块距离特例、界咆哮额外伤害没有一并自动套用。复杂技能点击名称查看和公告，再用手动牌区操作完成。木牛流马的储牌机制也保留人工裁定。自动范围详见上表，避免自动与手动重复结算。

## 手动与纠正

目标直接点击中央玩家框选择，再点一次取消；选中会高亮。铁索和借刀先选手牌，再按顺序点击两个玩家，框上显示1、2。点装备或判定牌只选牌，不切换目标。目标选择在当前浏览器保留，其他玩家操作同步时不会清空。

左侧「手动操作」可以补摸、翻牌、调整体力、随机取弃目标手牌。手牌下方「手动」可打出、装备、交牌、弃牌、放入判定区和转化。点击其他玩家装备/判定牌，可移动公开牌。私看牌顶按选择顺序放回，供观星等技能使用。

房主工具：

- 撤销上一步，版本仍递增；已公开的信息无法收回。
- 纠正：中止响应、设置体力/上限、切换目标回合及阶段、横置、重置杀/酒计数、补牌。必须填写原因，记录到公共日志。
- 中止拼点时，隐藏提交牌退还各自持有者；中止其他结算后，桌面牌留给玩家手动处理。
- 自动结算进行时先响应；需要手动改变牌区时由房主先中止，避免破坏待结算事件。

## 存档

房主每次合法变更后将完整状态写入本地IndexedDB，只保留最近主持的一桌。不要同时在同一来源的多个标签页主持。

刷新后恢复牌桌，重新邀请朋友；朋友在原标签页回应，凭保存在sessionStorage的token认领原席位。更换浏览器或丢失凭据不能自动找回。房主离线暂停，不自动迁主。响应队列和未公开拼点也可以恢复。

房主可导出/导入完整JSON，含隐藏牌、身份和token，请私下保管。v1旧存档会迁移为标准牌堆的自由手动局，保持原有牌区。协议升级为v2，联机双方都需刷新网页。


```powershell

```

可选浏览器测试：`node scripts/browser-smoke.mjs`、`node scripts/browser-rules.mjs`，需自行提供Playwright与Chromium；不影响项目运行。验证记录在 [docs/TESTING.md](docs/TESTING.md)，后续维护规则在 [AGENTS.md](AGENTS.md)。

## 发布与信任

将 `dist/` 内全部内容上传任意HTTPS静态托管即可，不需构建或远程游戏后端。`.openai/hosting.json` 只是本次Sites托管元数据，不是运行依赖。

后端位于房主浏览器Worker。普通玩家只收到自己的手牌、隐藏身份和候选，不能看到他人私有区或牌堆顺序。房主拥有完整状态，适合可信好友，未实现针对房主作弊的密码学防护。静态站点可公开，牌局与存档不上传托管服务。网络边界和协议见 [架构文档](docs/ARCHITECTURE.md)。
